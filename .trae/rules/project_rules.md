# Правила работы с проектом

Данный документ содержит основные правила и стандарты для работы с литературными текстами в проекте.


## 1. Правила работы с текстами

### 1.1 Распознавание текста

* Распознавание текста выполняется из PNG файлов с помощью OCR

* Исходные PNG файлы сохраняются вместе с обработанными текстами

* При обработке нескольких изображений создается единый связный текст

* Вариант распознанного текста обычно доступен в одноименном файле с расширением `.txt`, можно использовать текст из него, если он лучшего качества


### 1.2 Исправление ошибок

* **Орфографические ошибки**: исправляются все опечатки и неправильные написания

* **Грамматические ошибки**: корректируется согласование, падежи, времена

* **Стилистические улучшения**: улучшается читаемость и литературное качество

* **Удаление артефактов**: убираются технические пометки, лишние символы, следы OCR


### 1.3 Создание заголовков

* Заголовки создаются на основе содержания текста

* Должны отражать основную тему или ключевую фразу произведения

* Используется кириллица в оригинальном написании

* Если в тексте присутствует заголовок, он используется в качестве основного заголовка


## 2. Правила форматирования Markdown

### 2.1 YAML-заголовок (обязательный)

```yaml
---
title: "Название произведения"
date: YYYY-MM-DD
date_str: "DD месяц YYYY г."
layout: typewriter
category: prose  # или poems
---
```

### 2.2 Форматирование текста

* **Двойные пробелы**: добавляются в конце каждого абзаца для корректного отображения

* **Тире**: используются длинные тире (—) вместо дефисов в диалогах и по тексту

* **Диалоги**: оформляются с тире и правильными отступами

* **Разделители**: центрируются с помощью `<div style="text-align: center">   •   •   •   </div>`

### 2.3 Структура документа

* YAML-заголовок в начале файла

* Основной текст с правильным форматированием

* При необходимости — разделители между частями


## 3. Правила именования файлов

### 3.1 Основные принципы

* Используется кириллица

* Пробелы заменяются дефисами

* Все символы в нижнем регистре

* Исключаются специальные символы

### 3.2 Примеры именования

* "Новогодняя ночь" → `новогодняя-ночь.md`

* "Как хорошо, что ты есть" → `как-хорошо-что-ты-есть.md`

### 3.3 Связанные файлы

* PNG файлы именуются согласованно с основным файлом

* Добавляется номер для множественных изображений: `-01.png`, `-02.png`

* При переименовании основного файла переименовываются все связанные изображения


## 4. Структура проекта

### 4.1 Организация папок

```
_prose/
├── new/          # Новые материалы в обработке
└── done/         # Готовые материалы

_poems/
├── new/          # Новые стихотворения
└── done/         # Готовые стихотворения
```

### 4.2 Рабочий процесс

1. Исходные PNG файлы размещаются в папке `new/`
2. После обработки создается Markdown файл в той же папке
3. После финальной проверки файлы перемещаются в `done/` (вручную)
4. Исходные изображения сохраняются вместе с текстом


## 5. Технические требования

### 5.1 Jekyll совместимость

* Все файлы должны быть совместимы с Jekyll

* Используется layout `typewriter` для художественных текстов

* YAML front matter обязателен для всех документов

### 5.2 Категории контента

* `prose` — для прозаических произведений

* `poems` — для стихотворений

* Категория указывается в YAML-заголовке

### 5.3 Обработка изображений

* Исходные PNG файлы сохраняются без изменений

* Создаются текстовые версии с исправлениями

* Поддерживается связь между изображениями и текстом через именование


## 6. Контроль качества

### 6.1 Проверка перед публикацией

* Орфография и грамматика исправлены

* Форматирование соответствует стандартам

* YAML-заголовок заполнен корректно

* Имена файлов соответствуют правилам

* Связанные изображения переименованы согласованно

### 6.2 Сохранение оригинальности

* Сохраняется авторский стиль и интонация

* Исправляются только очевидные ошибки

* Не изменяется смысл и структура произведения

* Сохраняются авторские даты и пометки
